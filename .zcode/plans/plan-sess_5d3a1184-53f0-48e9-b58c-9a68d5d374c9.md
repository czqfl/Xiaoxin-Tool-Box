# 智能选区增强：浏览器元素识别精度 + 滚轮候选切换

## 背景与根因

项目已有智能选区（`uia_pick.rs` + 前端 `querySmartRect`），但浏览器场景失准的根因有二：

1. **Chromium 无障碍树首次激活延迟**（数百 ms~秒级）：呼出截图后首次悬停时 UIA 查询超时返回 None → "没反应"。
2. **逐层贪心下钻的精度缺陷**（`uia_pick.rs` 现有 `query()`）：每层 `FindAll(Children)` 选"最小面积子元素"逐层走，某层子节点 >600 直接放弃（大网页常见）→ 停在容器级；中间层钻错分支不回头；无 role 的 div 一直钻到 Text 碎片后被过滤 → "不准"。

## 改动一：`src-tauri/src/uia_pick.rs` 查询内核重写

- **主路径**：一次 `FindAllBuildCache(TreeScope_Descendants)` 全子树批量物化（CacheRequest 增加 `UIA_IsOffscreenPropertyId`），本地 O(n) 构建候选链：
  - 过滤：包含光标点、非 offscreen、≥6px；
  - 按面积升序（内→外）去重（相邻面积差 <5% 视为同层）；
  - **交互控件修正**：最内层若是非交互元素的小 Text/Image 碎片（<40×28，沿用现有阈值），链最内端回退到最近的可交互祖先（Button/Hyperlink 等，沿用现有 ControlType 表）；
  - 链上限 8 层；保留现有 <10px 噪点、与窗口等大、越界(±1px) 过滤。
- **fallback**：全子树 Err/空/节点数超上限(4000) 时回退到现有逐层下钻路径（保留代码，stack 即链）。
- **滚轮候选链**：`pick()` 返回 `Vec<ShotRect>`（内→外），memo 缓存同步改存链。
- **预热**：新增 `Msg::Warm { hwnd }` 与 `pub fn warm()`——worker 对目标窗口做一次轻量查询（ElementFromHandleBuildCache + FindAll，结果丢弃），提前触发 Chromium a11y 激活，解决"首次没反应"。

## 改动二：`src-tauri/src/screenshot.rs`

- `shot_ui_rect_at` 返回值 `Option<ShotRect>` → `Option<Vec<ShotRect>>`（语义：候选链）。
- `begin_impl` 快照写入后：用 `candidate_at(光标)` 找到光标下窗口，fire `uia_pick::warm(hwnd)`（异步，不阻塞主流程）。

## 改动三：`src/core/tauri.ts`

- `shotUiRectAt` 返回类型同步改为 `Array<ShotRect> | null`。

## 改动四：`src/modules/screenshot/ScreenshotOverlay.tsx` 滚轮切换

- `querySmartRect`：拿到链后最内层照旧参与择优显示，整条链存入 `snapChainRef`。
- **wheel 事件**（idle 且有链、链长 >1 时）：向上滚 = 更精细（内层），向下滚 = 更粗（外层），移动 index 并更新高亮（复用 commit 去重逻辑）；拖拽/缩放/新位置补查时 index 重置为 0。
- 单击采纳的就是当前 index 的矩形（单击逻辑不改，读当前 snap 即可）。
- 链长 >1 时在现有提示区域加一行轻提示「滚轮切换选区」。

## 验证

1. `cargo check` + `npx tsc --noEmit`。
2. 实际运行验证（需要你配合实测）：浏览器网页按钮/无 role 可点区域/首次呼出悬停；滚轮切换层级后单击采纳区域正确。

## 风险

- 超大页面全子树物化耗时：外层 220ms recv_timeout 兜底 + 节点上限回退逐层，最坏退化为现状。
- fallback 保证：任何全子树路径失败都回落到现有逐层逻辑，不会比现状更差。

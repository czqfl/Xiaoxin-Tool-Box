# 2026-08-29 工作日志

## 屏幕录制模块：崩溃修复 + 设置/面板统一 + UI 简化（4 项反馈）

### 1. 开始视频录制即崩溃 `0xc0000005 STATUS_ACCESS_VIOLATION`（根因级修复）

**现象**：点开始录制后进程直接退出，Rust 无 panic 信息；诊断日志停在
`[recorder] first frame captured: N bytes`，之后无任何输出。

**根因**：`src-tauri/src/dupl.rs` 的 DXGI 采集上下文缓存
`OUTPUTS: Mutex<Option<HashMap<(i32,i32), OutputCtx>>>` **只按显示器坐标作 key**，
而三个模块在各自 `std::thread::spawn` 的线程里调用同一份缓存：
- `screenshot.rs:174` capture_all（截图线程，每次截图新建线程）
- `scrollshot.rs:595` run（长截图线程）
- `recorder.rs:478` run（录制线程）

于是**录制线程复用了截图线程创建的 `ID3D11DeviceContext`** —— D3D11 immediate
context **不是线程安全的**，跨线程 Map/CopyResource 属未定义行为 → 访问违规。
日志佐证：先跑过截图（缓存已建）→ 再点录制 → 第一帧后崩。

**修复**：
- OUTPUTS 的 key 改为 `(ThreadId, i32, i32)`，每个采集线程独享 device/context/duplication。
- 新增 `dupl::win::release_thread()`（含非 Windows 空实现），按线程清理缓存。
- 三处采集线程入口各加 RAII guard，保证**所有退出路径**都释放：
  `recorder.rs` RecThreadGuard、`scrollshot.rs` ScrollThreadGuard、
  `screenshot.rs` capture_all 内 CapThreadGuard。
  ⚠️ 线程隔离后每个线程都会自建 D3D11 设备，**不释放就会每截一次图残留一套设备**（GPU 资源泄漏），三个 guard 缺一不可。
- `download()` 加固：Map 后校验 `pData` 非空且 `RowPitch >= stride`，不满足则
  **先 Unmap 再返回 None**（否则纹理一直挂 mapped 状态，后续采集全失败）。

### 2. 录制功能参数：帧率上限提高 / 去掉时长上限

## 第二轮反馈（4 条）

### 1. 录屏仍崩溃 0xc0000005 —— 上一轮根因不完整，真凶在编码器

上一轮修的「D3D11 跨线程」是真实隐患但**不是本次崩溃点**（新日志 `fps=24`
证明新代码已生效，却仍崩在第一帧之后）。第一帧采集后的路径只剩
`h264.rs::write_bgra`，复查发现：

**它每帧复用同一个 `IMFSample` / `IMFMediaBuffer`**，而 Media Foundation
SinkWriter 对已提交的 sample 是**异步消费**的——上一帧还在被编码器读取时就被
下一帧覆写，即典型的访问违规。

修复：
- `write_bgra` 改为**每帧新建 buffer + sample**（`new()` 里那对只作初始化探测）。
- Lock 后校验 `pData` 非空且 `cbMaxLength >= frame_bytes`，不满足则先 Unlock 再返回
  （否则 buffer 一直挂锁定状态，后续写帧全失败）。
- `recorder.rs` 记录写帧失败原因 + 前 3 帧各打一条 `[recorder] frame N encoded`，
  下次再崩就能从日志区分死在「采集后」还是「编码后」。

### 2. 录制面板再简化为一行

去掉「重选」（右键即可清空选区重选，功能不丢）、去掉「格式」标题；
格式由下拉框改为**平铺按钮**（Video/Image 图标 + MP4/GIF 短标签，选中态品牌色实底），
与「开始录制」同排，中间用竖线分隔。面板宽度改由内容撑开（`width: auto`），
宽高估算 320×214 → 250×62。
CSS 注意：`.rec-start` 原来靠 `.rec-actions .rec-start` 后代选择器生效，
改结构后必须同步改选择器，否则丢失样式。

### 3. 悬浮工具栏去阴影

工具栏本体早就是 `shadow:false` + 纯内高光。**阴影实际来自贴边收起时的
`toolbar-edge-breathe` box-shadow 外发光**（0 0 10px/22px）。
改为只让亮轨 `border-color` 明暗呼吸，保留可发现性但不再发光。

### 4. 悬浮提示被工具栏挡住 —— 独立窗口方案

根因：提示用的是**原生 `title`**，它是 WebView 的子窗口，z-order 永远低于
`alwaysOnTop` 的工具栏，显示出来就被自己压住。

**走过的弯路（重要教训）**：一度想扩大工具栏窗口、在窗口内预留提示区，
但**贴边收起是"把窗口滑出屏幕只露一条边"**——窗口一旦大于工具条，
贴底收起露出的就是透明的预留区而不是工具条，直接破坏收起功能。
（贴底收起只能露出窗口顶部、贴顶只能露出窗口底部，二者对条的位置要求相反，
无解。）已全部回退。

最终方案：**独立置顶提示窗口**（新增）
- `tauri.conf.json` 新增窗口 `toolbar-tip`（transparent / 无装饰 / 无阴影 /
  alwaysOnTop / skipTaskbar / 默认隐藏）。⚠️ 字段名是 `focus` 不是 `focused`，
  写错会导致 tauri-build 直接失败。
- 新增 `modules/toolbar/tip.ts`（事件通道 `toolbar://tip`）、
  `ToolbarTip.tsx`（监听 → 测量 → 置顶定位 → 显示）、`tip.css`。
- `Toolbar.tsx`：hover 按钮时把**按钮中心的屏幕坐标**（`outerPosition()/scaleFactor()`
  换算成 CSS 像素）emit 出去；鼠标离开 emit null 隐藏。
- 定位：横条→提示在按钮上方居中，竖条→在按钮右侧垂直居中；再按
  `screen.avail*` 夹回工作区。每次显示都 `setAlwaysOnTop(true)`，
  保证两个 TOPMOST 窗口之间提示浮在上面。

### 验证
`cargo check` 通过；`tsc --noEmit` 通过；`vite build` 通过。
⚠️ 环境注意：`vite build` 写入已存在的 `dist/` 文件会 EPERM（应用占用 +
safe-delete 保护），需输出到**全新目录**（如 `dist_check2`）才能验证；
临时目录因环境回收站不可用无法自动删除，需手动清理。

## 第三轮反馈（5 + 1 条）· 本轮【未经编译验证】由用户自行编译

> ⚠️ **教训（AI 造成的事故）**：绝不要在 `src-tauri/` 下创建临时
> `CARGO_TARGET_DIR`（本轮用了 `src-tauri/target_verify`）。它会落入
> tauri dev 的文件监视范围——目录内产物一变就触发 rebuild，rebuild 又改动
> 产物，导致 dev **无限重编译循环**（用户表现为启动后一直 Rebuilding）。
> 需要旁路编译时，target 目录必须指到项目外；dev 进程持有
> `.cargo-build-lock` 时也应直接交由用户编译，不要自建目录硬刚。
> 事后已终止相关进程并清理该目录（178M）。同类临时目录（dist_check2/3）
> 留在项目根不会触发 dev 重建，但仍属垃圾需手动清理。

### 0. MP4 仍崩溃 —— 真凶锁定为「硬件编码器驱动」

上一轮加的打点立功了，日志出现 `frame 1 encoded` 却无 `frame 2`：
**第 1 帧编码成功、第 2 帧死在 native 内部**（Rust 无法捕获）。
同时日志显示 GIF 完整录完 97 帧 —— 采集链路（上上轮修的线程隔离）已正常，
问题只在 MP4 编码路径。

结论：`MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS=1` 启用的 GPU 硬件编码 MFT，
在连续快速提交 BGRA 帧时会驱动级崩溃。
**修复：删除该标志，强制走软件编码器**（Microsoft H.264 Encoder MFT），
屏幕录制这种分辨率/帧率对 CPU 毫无压力，稳定性远高于各厂商驱动。
（改为软件后创建属性数量 2 → 1，同步改了 MFCreateAttributes 的容量参数）

### 1. 启动速度：选区窗不再销毁，改为复用

原流程每次录制都 `window.close()` 销毁选区窗，下次呼出要重建 WebView（一两秒）。
现改为**只 hide 不销毁**：
- `recorder_start` 不再 close 选区窗

- `begin_select` 复用分支：`show` + `set_focus` + emit `recorder://select-reset` 通知前端清空状态

## 端口工具修复：卡死 + 无法拖动
- 现象：查询时卡住、loading 不转、窗口无法拖动
- 根因1（卡死）：后端 `netstat` 同步阻塞无超时，环境异常时无响应 → 前端 await 永久 pending、loading 卡死
  → 提取 `run_netstat()` 用 thread+channel `recv_timeout(15s)` 包裹；前端 `portSearch` 再套 `withTimeout(20s)` 兜底（`f0204b1`、`643c6c2`）
- 根因2（无法拖动）：PortPanel 用 JS `startDragging()`，未接 usePanel 的 drag 守卫；查询期间 Tauri 命令通道被占时静默失败
  → 改用项目统一的 `data-tauri-drag-region`（原生拖动，接上守卫，交互元素自动排除），移除 onMouseDown 逻辑
- spinner 加固：`display:inline-block + will-change:transform`
- 提交：`f0204b1`（后端）、`643c6c2`（前端+拖动+样式）
- 教训：面板拖动必须用 `data-tauri-drag-region`，不要用 `startDragging()`；任何后端阻塞命令都要加超时

## 端口查询根治：dev 快 / release 卡
- 现象：tauri dev 查询 <1s，但打包安装版查询卡 2-4s
- 根因：每次查询启动 `netstat.exe` 子进程；安装版 exe 是全新文件，被 Windows Defender
  实时保护对每次拉起的子进程做扫描 → 每次查询都慢。dev 的 exe 在 target/debug 已被信任故快。
  （与前面"卡死"是不同根因：前者是异常无响应挂起，这是正常环境被安全软件拖慢）
- 根治：`port.rs` 移除 netstat 子进程，改用 Windows IP Helper API
  `GetExtendedTcpTable`/`GetExtendedUdpTable`（含 IPv4/IPv6 的 TCP/UDP），进程名复用
  `QueryFullProcessImageNameW`；端口字段网络字节序需 from_be 还原。零子进程 → 不受 Defender 扫描。
- Cargo.toml windows 新增 feature `Win32_NetworkManagement_IpHelper`
- 提交：`42cf80f`
- 教训：Tauri/桌面应用查询系统信息，优先用 Windows API 而非启动外部命令（netstat/tasklist 等），
  否则安装版易因杀软扫描子进程而卡顿

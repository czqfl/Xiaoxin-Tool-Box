# 2026-08-11 工作日志

## 五项反馈修复（剪贴板漏记 / git 终端体验 / VS Code 定位）

### 1. 剪贴板偶尔漏记（clipboard.rs）
- 根因 A（关键）：`watcher_tick` 里 `SUPPRESS_WATCH.swap(false)` 在 `hash == last_hash` 判断**之后**才执行。
  当从面板写回的内容与当前剪贴板快照相同（hash 相等提前 return）时，suppress 标记残留为 true，
  下一次外部应用的复制会被当成"主动写回"跳过 → 表现为"偶尔复制的内容进不了历史"。
  → 修复：把 swap(false) 移到 hash 比较之前，无条件消费标记。
- 根因 B：`read_clipboard` 失败（源应用延迟渲染/剪贴板被占用）直接 return，可能漏记。
  → 修复：`watcher_tick` 改返回 bool（是否读到快照），`start_watcher` 循环在连续失败时用 120ms
  短超时快速重试（上限 8 次后回落 500ms），panic 分支重置计数。
- 经验：`SUPPRESS_WATCH` 这类"消费型标记"必须在所有提前 return 路径之前消费。

### 2. git 命令先弹终端再执行 + 单行整洁显示（folder.rs exec_in_shell）
- cmd 分支：`@echo off & mode con 150x9999 & cls & cd /d "path" & echo. & echo $ cmd & timeout /t 1 /nobreak >nul & cmd`
  - `@echo off` 开头：整行因 @ 前缀不回显；`cls` 清掉启动痕迹；`timeout 1 秒` 让窗口先弹出停在目录，
    再执行命令，输出从头滚动；`echo $ cmd` 只显示一行命令，不换行不杂乱。
- powershell/wt 分支：`Clear-Host` + `Write-Host '> cmd'` + `Start-Sleep -Milliseconds 800` 同理。
- 多命令：命令字符串支持 `\n` 分隔（如 add+commit+push 一条龙），后端按 shell 拼分隔符：
  cmd 用 `&`、PowerShell 用 `;`（PS 5.1 不支持 `&&`，必须用 `;`）。

### 3. 一键提交并推送（FolderPanel.tsx GIT_COMMANDS）
- 新增组合项：`git add .\ngit commit -m "update"\ngit push`（label：一键提交并推送）。

### 4. VS Code 定位（folder.rs + config.rs + 前端）
- 根因：`open_vscode` 只查 PATH code + LOCALAPPDATA/Program Files 两个标准位置；用户机器全盘
  常见位置都搜不到（PowerShell 递归扫描无果），疑似便携版/自定义目录。
- 修复：`FolderConfig` 新增 `vscode_path: Option<String>`；`open_vscode` 探测顺序 =
  配置路径 → PATH code → 标准安装 → 盘根/scoop → 受限全盘扫描（find_vscode_exe，只深入名字含
  code/vscode/microsoft/tools 等的目录，深度≤4）。全失败返回特殊错误 `VSCodeNotFound`。
- 前端：`openInEditor` catch 到 VSCodeNotFound 时，弹文件选择器（pickVscodeExecutable，
  dialog filters exe）让用户手动选 Code.exe → 调新命令 `folder_set_vscode_path` 持久化 → 重试打开。
- 新命令 `folder_set_vscode_path` 已注册进 lib.rs handler。

## 二次反馈修复（设置面板偶发打不开 / 面板滚轮）

### 1. 设置面板偶尔打不开（tray.rs + acrylic.rs）
- 根因：`show_settings_window` 用 Tauri 异步 `set_always_on_top(true)` 后立即调
  `force_foreground`（同步读 Win32 样式）。异步时序下可能读到"尚未置顶"，force_foreground
  走"顶到最前再降回"分支 → 把设置窗口降成普通窗口 → 被其它窗口盖住 → 表现为打不开。
- 修复：新增 `acrylic::force_topmost_foreground`——`SetWindowPos(TOPMOST)`（同步生效，
  SWP_NOACTIVATE）再 `SetForegroundWindow`，不依赖异步 IPC。show_settings_window 改用它，
  删除 tray.rs 内不再使用的 force_foreground_window（注意保留 Manager import，get_webview_window 需要）。

### 2. 面板鼠标悬停即可聚焦（滚轮可用）（usePanel.ts）
- 根因：WebView2 在窗口非活动（失焦）时不响应滚轮，呼出后面板滚不动、要点一下才行。
- 修复：`usePanelCommon` 挂 document 级 `mouseover` + `mousedown` 监听，`!document.hasFocus()`
  时调 `getCurrentWindow().setFocus()`。鼠标一进面板即聚焦，滚轮立即可用（有真实鼠标输入时
  Windows 允许置前）。hasFocus() 为 true 时直接 return，无额外开销。
- 编译验证：cargo build + npm run build 通过。

### 3. 启动偶发崩溃：state() called before manage()（根治）
- 现象：启动偶发 panic `state() called before manage() for config::ConfigState`，
  栈在 tauri app.rs → WebviewWindowBuilder::build → wry attach_ipc_handler →
  WebResourceRequestedEventHandler（COM 回调不能 unwind → STATUS_STACK_BUFFER_OVERRUN 崩溃）。
- 根因：配置声明的窗口在**用户 setup 回调之前**创建；窗口创建时 webview IPC 初始化会
  访问 state，而原代码 manage 全在 setup 回调里 → 与页面加载/命令调用形成竞态，偶发 panic。
- 修复（Tauri 标准解法）：state 注册**提前到 Builder 级**（Builder::manage 在 App 构建、
  窗口创建前生效）：
  - `AppPaths::resolve()` 去掉 AppHandle 依赖：fallback 改用 `%APPDATA%/{identifier}`
    （与 Tauri app_data_dir 的 RoamingAppData+identifier 一致，数据不丢）。identifier 是
    `com.xiaoxin.toolbox.app`。
  - lib.rs：run() 开头同步 resolve+load_json，Builder 链上 `.manage(...)` 注册全部 6 个
    state（ConfigState/ClipboardStore/FolderStore/CredentialStore/ShortcutBindings/AppPaths），
    setup 闭包改 `move`（捕获 config），仅保留 tray/keyhook/shortcut/watcher 初始化。
- 双保险：panel.rs 两处 `state::<ConfigState>()` 硬取改 `try_state` + `unwrap_or(true)`，
  任何时序下不 panic。
- 经验：Tauri 里凡是"窗口创建时可能被访问的 state"（尤其命令参数注入 State<T>、前端
  mount 即调用的命令），都用 Builder::manage 提前注册；读取侧尽量 try_state。

## 一键打包脚本（scripts/build-release.ps1 + npm run release）
- 一条命令产出三类产物到 `dist-release\`：
  - `小心工具箱-安装版-v<版本>.exe`：NSIS 安装包
  - `小心工具箱-安装版-v<版本>.msi`：MSI 安装包（需 WiX，首次构建自动下载；失败自动回退仅 NSIS）
  - `小心工具箱-便携版-v<版本>.zip`：绿色版（复制 release exe 为「小心工具箱.exe」+ 空 data\ 目录
    + 使用说明；AppPaths 便携逻辑：exe 同级 data\ 可创建即作为数据目录）
- 实现：`npm run tauri build -- --bundles nsis,msi`；NSIS+MSI 失败则回退 `npm run tauri build`（仅 NSIS）。
  打包阶段直接通配收集 bundle\nsis\*.exe、bundle\msi\*.msi。
- 用法：`npm run pack`（完整）或 `.\scripts\build-release.ps1 -SkipBuild`（仅打包）；
  产物输出到**项目根目录**（用户要求最顶层，不走 dist-release/）；.gitignore 已忽略
  `小心工具箱-安装版-*.exe/.msi`、`小心工具箱-便携版-*.zip`、`stage/`。
- 注：release exe 名是 xiaoxin-toolbox.exe（Cargo bin 名），便携版复制时重命名为「小心工具箱.exe」；
  npm script 里用 `powershell -NoProfile -ExecutionPolicy Bypass -File` 调用（Bash 里直接调 powershell 会被安全策略拦）。

## 顺序粘贴队列增强（下一个置顶 / 撤销 / 加入队列）
- 队列语义：FIFO/LIFO 都按 created_at 排序，前端 buildQueue 与后端 sequential_paste 一致，
  队首 = 下一条。`queue[0]` 即下一条。
- **下一个置顶展示**：ClipboardPanel 顺序模式下 displayList = buildQueue(filtered, mode)（不再走
  置顶/历史分区），列表整体按队列顺序，下一条在列表第一项；切换 FIFO/LIFO 即调整展示顺序。
- **撤销上次粘贴**：后端 `LAST_CONSUMED: Mutex<Option<ClipEntry>>` 记录最近一次被消耗的条目；
  sequential_paste（全局 Ctrl+V）与新命令 `clipboard_consume`（面板手动粘贴）两条消耗路径都记录，
  消耗时**不再删图片文件**（保证回滚完整恢复）；`clipboard_rollback` 按原 created_at 插回队列正确
  位置（FIFO 回队首附近、LIFO 回队尾附近），幂等跳过已在队列的。前端 footer 顺序模式显示「↩ 撤销上次」。
- **加入队列 → 设为下一条**：`clipboard_enqueue(id)` 最初设计为 created_at 置 now（LIFO 立即下一条、
  FIFO 排队尾），用户反馈"点了没反应、不好用"。**已改为「设为下一条」**：created_at 放到当前模式
  队首前一位（LIFO 置 now；FIFO 置最旧-1，saturating_sub 防溢出），无论哪种模式点击后立即成为
  Ctrl+V 带出的下一条，列表同步排到第一项。ClipboardItem「+」按钮 title 同步更新。
- 孤儿图片清理：`cleanup_orphan_images` 在 clipboard_clear 时删除 images 目录未被任何条目引用的文件
  （被消耗未撤销的图片残留由此回收）。

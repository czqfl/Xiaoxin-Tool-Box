#### 主人提供高精度矢量素材时的复刻路径（贴图图标一比一）
**触发**：用户提供了一张 1745×1920 的贴图 PNG，要求一比一复刻（含针刺粗细），不允许简单再绘。

**工具链**：
- `pip install potracer pillow numpy` （potracer 是 potrace 的纯 Python 绑定，免编译 cairo）
- 不要 `pip install cairosvg`，依赖 cairo 二进制（Windows 缺 libcairo-2.dll），会装失败
- svglib 也缺 reportlab cairo backend

**关键 pitfall**：
1. potrace 返回的 curves 列表里**第一个通常是画布外框**（bbox = 整张图），要按 `area < canvas_area * 0.9` 过滤掉。
2. **不要上采样**原图（之前试 8x NEAREST 上采样结果产生 117KB 爆量 SVG path，因为 jpg 抗锯齿边缘每个像素都成了 L 段）。
3. 原图已足够清晰（1745×1920）→ 直接 trace，turdsize=20 滤掉小块噪点，alphamax=1.3 让边缘更顺，opttolerance=0.6。
4. 单路径 2.4KB，比 Lucide 同尺寸图标还小，浏览器 SVG 渲染无压力。
5. PNG 透明背景 → PIL 读 alpha 通道过滤；JPG 无 alpha → 直接按灰度阈值（`< 230`），原图前景 ~#595959 灰度 ~89，背景 255。

**生产路径**：
- 复用 `trace-pin.py`（项目根），改 src 路径 + 调阈值即可批量化生成图标矢量
- Trace 出来的 path 存到 `*.const.ts` 文件（`export const X_ICON_PATH = "..."`），React 组件 import 后用 `<path d={X_ICON_PATH} fill="currentColor" />` 渲染
- `fill="currentColor"` 让图标自动跟随主题（亮暗色都用 currentColor）；实心剪影不要用 stroke

## 截图工具栏主题化：明暗两态（commit d703f7c，已 commit，未 push）

## 截图工具栏主题 bug 修复 + 深底 #202021 + 高级白（commit 5f772ad）
**触发**：主人反馈「浅色系主题下工具栏底色还是黑色」，并补充——深底不要纯黑
(rgb(32,32,33))，浅色底不要纯白（高级白）。

**根因（关键 bug）**：上一版把 `--tb-*` 令牌的默认值**直接写在 `.shot-toolbar-float`
容器上**（深色调）。CSS 自定义属性解析规则：子元素优先用「最近祖先上**直接设置**的值」，
`.shot-toolbar` 作为 `.shot-toolbar-float` 的子元素，永远读到父容器直接赋的深色
令牌，而读不到 `html[data-theme="light"]` 在顶层设的浅色值 → 浅色主题下工具栏恒黑。

**修复**：
1. 移除 `.shot-toolbar-float` 上的 `--tb-*` 直接赋值（消除继承遮蔽）。
2. 令牌重排为「默认浅色 + 仅 dark 翻深」：把浅色值定义在 `html { … }` 作为默认，
   仅 `html[data-theme="dark"]`（及系统深色媒体查询）翻到深侧。
   这样 light/mint/skyblue/red/orange 全部浅色系主题都拿到浅色工具栏，
   不再掉回黑底（之前只认 `data-theme="light"`，彩色浅色主题也黑底）。
3. 深底 #000 -> `rgb(32,32,33)` = #202021 近黑深灰（非纯黑）。
4. 浅底 #fff -> `#f5f5f7` 高级白（Apple 同款 off-white），图标深字 #2b2f36 不变。

**踩坑教训（可复用）**：用 CSS 变量做「主题令牌」时，**绝不要把令牌默认值写在
中间容器上**——只能通过继承从 `:root`/`html` 往下传，否则任何子元素/容器一旦
「直接赋值」就会遮蔽祖先的主题值，造成"某主题下样式不生效"的诡异 bug。
正确模式：`:root`/html 设主题值，具体组件只 `var()` 消费，不在中间层 set。

校验：`npx --noEmit tsc` 通过。仅改 screenshot.css。

## 截图工具栏箭头图标重做：翼形流线箭头（commit edde375）
**触发**：主人反馈两点——①矩形/椭圆图标"没有变化"（怀疑 dev 没热更，需重启验证）；②"优化箭头，模仿企微里面的箭头，尾部窄，头部宽"。

**原状**：Lucide `ArrowUpRight`（折线+三角头标准图标），缺企业微信那种整体成型的流线感。

**实现**：
- 主人提供一张黑底+红色翼形流线箭头 PNG 作参考图。
- 复用 `trace-pin.py` 流水线生成 `trace-arrow.py`（仅改 src 路径+输出文件名），从 PNG 提取 SVG path：272 字符单路径。
- **关键踩坑**：原图是黑底红箭头，按灰度 `< 230` 阈值会把黑底也当前景（fg pixels = 整图）。必须按 **RGB 红通道分离 mask**（`r > 100 & r - g > 30 & r - b > 30`）才能正确只 trace 红色前景。
- 提取出来是水平翼形（细左、粗右），加 `transform="rotate(-45 12 12)"` 转到 45 度斜向上方向（粗端朝右上，与原图标方向一致）。
- `fill="currentColor"` 实心剪影，自动跟随工具栏主题色；不再用 stroke 描线（与 IcoPin 同风格）。
- 新增 `arrow-path.const.ts` 存 path 常量；移除不再使用的 lucide-react `ArrowUpRight` import。

**复用经验沉淀**：trace-pin.py 现在已可作通用「PNG/JPG → SVG path」流水线：
- 前景 vs 背景识别根据图像类型选：
  - 透明 PNG → `alpha > 128 & gray < 230`
  - 白底 JPG → `gray < 230`
  - 黑底红/绿/蓝前景 → 按 RGB 通道分离（`r - max(g,b) > 阈值`）
- 不要上采样原图（直接 trace，opttolerance 0.6 控点）
- 多 curve 时按 area < canvas_area*0.9 过滤画布外框
- 缩放到 viewBox 24 时 target=20（留 2px 边距）

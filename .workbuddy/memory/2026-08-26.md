## 🔥 贴图右键菜单重构为独立透明窗（pin-menu，未 push）
- 主人反馈：别的 AI 改的"临时扩窗"方案很糟——贴图小时右键菜单看不全，且会**自动把贴图撑大**、仍被裁。明确要求：菜单**彻底离开贴图边框、绝不改贴图尺寸**。
- 旧方案根因：菜单是贴图窗 webview 内 DOM 节点，必被 OS 窗矩形裁切；为塞下菜单只能 `setSize` 扩贴图窗，且改写尺寸、贴屏边仍溢出。
- 新方案：`onContext` 不再建 DOM 菜单，改为 `new WebviewWindow("pin-menu-<ts>", {...})` 动态建**独立透明窗**（decorations:false / transparent:true / alwaysOnTop / skipTaskbar / 初始 visible:false），经 URL query 传 `items`(菜单项JSON)、`cx/cy`(光标绝对屏幕逻辑坐标)、`pin`(来源贴图窗 label)。**唯一标签**规避重复建窗竞态，命中 `pin-*` 权限通配。
- 菜单窗 `PinMenu.tsx`：读 query 渲染 `.pin-ctx-menu`（复用 pin.css 玻璃底，随主题）；`useLayoutEffect` 量 `offsetWidth/Height` → `setSize(LogicalSize)` → 按 `cx,cy` 用 `setPosition(LogicalPosition)` 贴边（溢出右/下则翻到光标左/上）→ `show()`+`setFocus()`（先在显示前完成，无尺寸闪烁）。点击项 `emitTo(pin, "pin-menu-action", {id,pin})` 回传后 `close()`；Esc/失焦 `close()`。
- 来源贴图窗：`getCurrentWindow().listen("pin-menu-action")` 过滤 `pin===winLabel` 后由 `runMenuAction(id)` 执行（沿用旧 copy/toggle-shadow/toggle-clickthrough/hide/close 逻辑）。菜单窗自管 Esc，删除了原 keyboard effect 里 `menuRef/closeMenu` 拦截块。"clickthrough" 文案统一为"鼠标穿透"。
- 权限：`default.json` 增补 `core:webview:allow-create-webview-window`（`WebviewWindow` 真正所需；`core:window:allow-create` 为 Rust 侧，保留无害）。`main.tsx`/`App.tsx` 加 `pin-menu*` 路由与 `dataset.window="pin"`（pin.css 强制透明）。
- 校验：`tsc --noEmit` 通过。注意 `WebviewWindow` 来自 `@tauri-apps/api/webviewWindow`（非 `window`），`PinMenu` 为默认导出，菜单窗 `url` 用 `index.html?...` 显式相对路径。

## 快捷键推倒重来式重构，根治改键残留/卡死（commit e2a9daa，不推送）
- 主人反馈：快捷键「改键后新键不生效 + 旧键一按卡死」；改回原键也不生效。
  怀疑旧配置残留，要求"完全删掉原有快捷键逻辑重写"。
- 诊断过程：
  1. diag.log 实锤：主人今天测试的是**含 screenshot/pins（截图/贴图）的未提交新功能**
     版本（源码 15:38 改、exe 15:40 构建），git 里 screenshot/pins 是未提交工作树。
  2. 三份配置（dev target/debug/data、项目根 data、%APPDATA%）shortcuts 各异，
     存在历史遗留 target 字段（screenshot/pins）；用户曾把功能键设为纯 F6
     （前端已允许 F1~F12 单独使用，如 F1 截图）。
  3. 旧 apply 流程「先注册新键→成功才注销旧键」：旧键注销环节一旦出岔子
     → 新旧混存（旧键继续触发=卡死、新键被旧键占位不生效）。
- 重写（src-tauri/src/shortcut.rs）：
  - `shortcut_apply`：校验 → **全量注销**（插件 unregister_all + keyhook 钩子槽位
    清零 + 绑定表清空）→ 按更新后配置**全部重建** → 任一失败**自动回滚**原配置
    重建并返回错误。改键=全新状态，运行时与配置严格一致，无新旧混存。
  - 新 helper 消灭 if-else 地狱：TARGETS 常量表 / config_shortcut /
    set_config_shortcut / set_binding / register_one_result / resync_all_result。
  - register_initial / resync_all 统一走 resync_all_result；启动失败留痕+开设置页。
  - 删除不再需要的 unregister_combo。
- 前端配合已有：设置页有「重置并重新注册全部快捷键」按钮（shortcut_resync）+
  「运行时实际生效」展示（shortcut_runtime_bindings），脱节一眼可见。
- 提交含未提交的截图/贴图功能（pin.rs/screenshot.rs/前端模块）——shortcut.rs

## 截图矩形框/放大镜/取色面板在 150% DPI 下错位（未提交，待验证）
- 主人：截图矩形框"从某点拉、右下角不跟手、又错位"；环境 150% DPI
  （2560×1600 物理 / 1707×1067 CSS，见 StickyNote 双窗口坑记录）。
- 根因（两处同源 DPI bug）：
  1. 选区画布 `selCanvas` 用 `getContext("2d", {desynchronized:true})` 低延迟画布。
     该模式在 DPR≠1 的 Chromium 下存在**合成偏移**：内容按 DPR=1 合成、窗口是
     1.5×，**越远离原点偏移越大**——起点（左上、靠原点）看着对，右下角（远原点）
     整体偏出去、不跟手。这正是"矩形框又错位"。
  2. 放大镜 `drawMagnifier` 与取色 `updatePickerVisual` 把**画布位图坐标
     (0..geom.width)** 直接当 **CSS 像素**用于 `position:fixed` 的 left/top，
     在 150% 下整体偏移一个 DPR 系数（≈1.5×）。
- 修复（src/modules/screenshot/ScreenshotOverlay.tsx，纯前端、无需 Rust 重编译）：
  1. 选区画布去 `desynchronized`（改 `getContext("2d")`）；拖拽低延迟由 onMove
     快速路径（事件内同步 paintSelCanvas，不经 rAF/state）保证，不回退卡顿。
  2. 放大镜/取色定位统一按 `k = 显示宽/位图宽 (= rc.width/geom.width)` 把位图坐标
     折算成 CSS 像素；镜头采样仍在位图坐标系内无需转换；边界翻折改用
     window.innerWidth/innerHeight（CSS px）。
- 注：选区矩形/工具栏/文字编辑器用 `scale = bgRect.width/geom.width`（显示/位图）
  折算，原本就正确，未动。
- 验证：tsc --noEmit 通过（EXIT=0）。待主人重启 `npm run dev:app` 实测
  150% 下矩形右下角是否精确跟手、放大镜/取色面板是否贴光标。
- 经验：**高 DPI 下 canvas 选区用 desync 低延迟画布会合成偏移**；凡把画布位图
  坐标喂给 DOM `style.left/top`（CSS px）都必须除以 DPR（×显示宽/位图宽）。
  本项目用户固定 150% DPI，所有"画面坐标→DOM 定位"都要过这一折算。

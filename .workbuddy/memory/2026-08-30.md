## 录屏：录制中随时开关录音（按钮此前从不显示）

**根因**（用户反馈"其他 AI 加了但没显示"）：`RecorderBar.tsx` 的麦克风/音量按钮被 `{audioOn && …}` 包裹，`audioOn` 取自 Rust `AUDIO_STATE==1`，而该标志只在 `AudioEngine::start()` 成功启动端点时置位；`recorder.rs` 又是 `if opts.audio != Off` 才调 `start()`，而音源默认就是 `"off"`（启动栏/设置页/`unwrap_or` 三处默认）→ 条件永不满足。不是 CSS 藏了，是压根没渲染。

**更深层限制**：MP4 音轨在 `H264Writer::new_ex(..., audio_cfg)` 创建时即固定，启动时 `audio_cfg=None` 则成品无音轨，中途再点也录不进声。所以仅修显示无意义。

**方案（用户选定「预留音轨 + 按需采集」，默认跟随音源设置）**：
- `recorder.rs`：MP4 一律预留音轨（`set_available(true)`），音源非 off 时开场即启动采集并 `set_rec_on(true)`；GIF 仍不预留。
- `recaudio.rs` 新增：`AUDIO_AVAILABLE` / `AUDIO_REC_ON` / `AUDIO_SRC` / `AUDIO_SLOT: Mutex<Option<AudioEngine>>` / `AUDIO_STOP_REQ`、`reset_session()`、`apply_pending()`、`drop_slot()`，命令 `recorder_audio_rec(on) -> bool`（同步返回真实状态，失败时前端回滚）。引擎由命令线程创建、经 SLOT 交录制线程接管——`drain`/`finish` 必须与录制线程同侧（IMFSinkWriter 要求串行化）。
- 前端：`recSupported`（显隐，仅看格式）+ `recOn`（状态），音量按钮仅在 `recOn` 时出现（省横向空间且关闭时调音量无意义），失败内联提示 `.recb-rec-tip`（窗口仅 36px 高，条外气泡会被裁掉）。

**顺带修掉的 4 个缺陷**：
1. `AUDIO_STATE` 不随会话复位 → 上次带音频录完后，本次以 off 开录会残留 1，亮出点了没反应的死按钮（`recorder_start` 原先只复位 `AUDIO_MUTE`，还重复写了两遍）。
2. `AudioEngine::finish()` 不归零 → 「关录音→再开」被误判为"采集仍在跑"而直接置位，实际引擎已 finish、一个字节也录不进来。
3. 暂停期间开录的引擎滞留在 SLOT 收不掉 → 采集线程泄漏。修复：暂停分支每帧调 `apply_pending`（不能只放在 `if !was_paused` 里），结束/取消两处加 `drop_slot()` 兜底。
4. 带音轨 writer 创建失败回退无音轨时未收回按钮 → 补 `set_available(false)`。

**验证**：`cargo check` 通过（仅 3 个历史遗留警告）、`cargo test recaudio` 4 passed、`tsc --noEmit` 通过、`vite build` 通过。本地 commit `aa30aeb`，未推送。

**注意**：提交时工作区还混有他人未完成的改动（`pin.rs` 的 `pin_busy` 待命窗顺延补建、`sticky/history.ts` 便签绿色竖条），已通过「备份 lib.rs → checkout → 只重放自己的改动 → 提交 → 还原备份」的方式隔离，他人改动原样留在工作区未提交。

## 录制条音量面板：改为竖条 + 窗口动态加高

**问题**：用户反馈点音量按钮没反应。根因是 `.recb-vol-pop` 用 `top:-34px` 向上弹，而录制条窗口固定 36px 高（`recorder.rs` 的 BAR_H）且贴在屏幕顶部（by = my+12），面板整块落在窗口可视区之外 → 被 WebView 裁剪。调 z-index 无效，这是窗口边界的硬限制。

**修复**：
- 面板改为向下展开（`top: calc(100% + 6px)`），滑杆改竖向：`writing-mode: vertical-lr` + `direction: rtl`（让 0 落在底部、上拖增大，否则拖上去反而变小）；保留 `-webkit-appearance: slider-vertical` 兜底老版 WebView2（Chromium 121+ 才对 range 支持 writing-mode）。
- 关键点：**窗口必须临时加高**，36px 装不下竖条。点开时 `getCurrentWindow().setSize(new LogicalSize(356, 36 + VOL_EXTRA_H))` 撑到 144，收起还原（VOL_EXTRA_H=108；356/36 与 Rust 的 BAR_W/BAR_H 对应）。
- `.recb-root.vol-open` 改 `align-items: flex-start; padding-top: 5px`——否则整排按钮会随窗口变高而沉到中间。padding-top 取 5px 是因为按钮高约 26px、原 36px 内垂直居中时 top 正好是 5px，展开时不跳动。
- 三处联动收起：Esc 先收面板（否则调音量顺手按 Esc 会把整段录制结束掉）；phase 变为非 recording 时收起（否则被 toast 尺寸逻辑压扁）；`recOn` 变 false 时收起（否则窗口被撑高、面板所在按钮却不渲染，留一块空白）。

**经验（可复用）**：Tauri 无边框小窗口里做任何弹出层，先确认窗口高度容不容得下——超出部分一律被裁剪，只能动态改窗口尺寸，纯 CSS 无解。

## 音量面板改独立浮窗 + 录制选区窗背景透明

**① 撑高录制条那条路走不通，改独立浮窗 rec-vol**
上一版"点音量时把录制条窗口从 36 撑到 144"被否：用户看到"下方多出一个大白框"。原因是亚克力（SWCA）是**窗口级**效果，撑高多少就铺满多少；而 `.recb-root` 的背景 `color-mix(in srgb, var(--tb-bg) 78%, transparent)` 因 `--tb-bg` 未定义（**该变量只定义在 screenshot.css，录制模块没引入**）而整条失效，压不住亚克力 → 新增区域就是一整块毛玻璃。

改为独立浮窗（`VolumePopover.tsx` + `volume-popover.css`，label `rec-vol`，已在 capabilities 的 windows 数组登记）：
- 录制条始终保持 36px 条状，面板悬在音量按钮下方，各自管各自背景
- 复用单例（hide 而非 close，重建 WebView2 要几百毫秒）
- 竖条用 **rotate(-90deg) 而非 writing-mode**：writing-mode 要 Chromium 121+ 才对 range 生效，老版 WebView2 会退化成躺着的横杆、拖动方向全反；rotate 各版本一致，且 -90deg 让最大值端朝上
- 数值 `min-width: 40px` + `tabular-nums`，否则 9% 与 100% 会把面板撑得忽宽忽窄
- 通信：音量真实值在 Rust 侧，面板挂载读一次、拖动写回；关闭时 emit `rec-vol-closed` 让录制条重读刷新

**② 录制选区窗"像在截图上框选"的真正原因**
选区窗**根本没有截图**（无 img / 无 background-image，Rust 侧也没传位图），是纯透明窗 + CSS 遮罩 `rgba(0,0,0,0.20)`。真正的病根是页面底色不透明：
- `main.tsx` 按 label 给 rec-select 设了 `data-window="panel"`，但提供 `html[data-window="panel"] body { background: transparent }` 的 **panel.css 从未被录制模块引入**（RecorderSelect / RecorderBar 都只 import recorder.css）
- `base.css` 只设了 `height/overflow`，未设 background
- 按 CSS 规范，**根元素无背景时 UA 会绘制不透明白色 canvas**。`make_webview_transparent` 只管 WebView 控件的默认背景，管不到页面这层 canvas —— 于是白色把桌面整个盖住，选区里看到的就是一块静止实色
- 修复：recorder.css 自给该规则（两窗共用），并在 `begin_select` 复用分支补一次 `make_webview_transparent` 双保险

**经验（可复用）**：Tauri 透明窗口要真正透出桌面，必须**同时**满足两点——WebView 控件背景透明（SetDefaultBackgroundColor）+ **页面 html/body 显式 `background: transparent`**。少后者就一定是一块实色，且极易被误判成"截了张图"。

**用户追问"是不是真的截了屏"时的排查结论（重要）**：
录屏框选阶段**根本不存在截图**，可据此直接排除怀疑——
- `recorder.rs` 全文无 CreateWindow / SetParent / bitmap / BitBlt，即没有原生冻结层
- 作为对照，`screenshot.rs` 才有 `native freeze layer` + `attach_freeze_layer`（那才是真·截屏贴位图）
- 快捷键 `recorder` → `recorder::begin_select`，与托盘/命令面板同一条路；截图模块里也没有任何录屏入口
所以"像在截图上框选"只能是页面底色不透明导致观感如此，不是真的有截图。

## 控制条"没有圆角的边框"最终根治（重画窗口方案）

- **前一轮判断错误**：以为是窗口级模糊（blur）铺满矩形窗口导致方形边，移除 blur 后
  用户反馈边框仍在 → 真正根因是【透明窗口 + WebView2 合成】：`transparent:true` 的

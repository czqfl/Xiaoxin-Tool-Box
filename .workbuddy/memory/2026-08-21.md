- 主人多次反馈"关闭按钮/Esc 无法退出、面板无法拖动"，此前所有前端修复（drag-region 结构、
  双路绑定、弹窗状态重置）都是治标——**真凶是 `src-tauri/capabilities/default.json` 的
  windows 列表漏了 `"files-panel"`**：该窗口从创建起就没有任何权限！
- 后果（全部被系统拒绝）：
  - `core:window:allow-hide` 缺失 → `getCurrentWindow().hide()` 被拒 → 关闭按钮/Esc 全部无效
  - `core:window:allow-start-dragging` 缺失 → 头部拖拽区拖不动面板
  - `core:event:allow-listen` 缺失 → 弹窗状态重置监听注册失败
  - 其它面板都在列表里，所以只有 files-panel 有这些怪病；自定义命令（quickfiles_*、
    panel_set_always_on_top）不经 capability 校验，所以功能正常、面板内容正常显示
- 修复：windows 数组加上 `"files-panel"`；`cargo check` 通过（tauri-build 编译期校验）。
- **经验：新增面板窗口必须同步更新 capabilities/default.json 的 windows 列表**，
  否则"关闭/拖动/事件监听"等核心能力静默失效，且错误被 `.catch(console.error)` 吞掉无提示。
- 悬浮色：卡片 hover 由"叠中性底色"改为"直接加重类型色"（4%→14%、边框 16%→50%），
  避免冲淡颜色。

## 快速文件面板无"不透明度+实时模糊"：webview 背景未设透明（第二个遗漏 files-panel 的地方）
- 根因：`lib.rs` 的 `apply_panel_acrylic` 启动列表（CLIPBOARD/FOLDER/CREDENTIAL/PORT/
  TOOLBAR/TRANSLATE）漏了 FILES_PANEL，而该函数是唯一调用
  WebView2 `SetDefaultBackgroundColor(A:0)` 的地方 → files-panel 的 webview 底色不透明，
  把 SWCA 亚克力模糊整个盖住：面板变"实心"，不透明度调低也只会透出白色而非模糊。
- 修复（lib.rs）：
  1. 启动列表补上 `panel::FILES_PANEL`；
  2. 把 webview 透明背景提取为 `make_webview_transparent`，并在
     `apply_panel_effects_for` 末尾每次显示都调用——顺带修复"窗口被销毁重建
     （ensure_panel_window）后新建 webview 不透明"的同类隐患（所有面板受益）。
- 经验：**新增面板窗口要检查三处**：① capabilities/default.json 的 windows 列表
  （否则关闭/拖动/事件监听全部静默失效）；② lib.rs apply_panel_acrylic 启动列表
  （否则无亚克力模糊+webview 不透明）。

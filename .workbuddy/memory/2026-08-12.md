## 剪贴板 FIFO/LIFO 拖拽排序释放闪烁修复
- 现象：顺序模式拖动排序松手时列表"闪一下"（先跳回原位、再跳到新位）。
- 根因：`finishDrag` 松手时立即 `setVisualOrder(null)`——displayList 从拖拽中的视觉顺序
  瞬间跳回按 created_at 的旧队列顺序（被拖条目跳回原位置），随后 `reorderQueueEntry`
  调后端 `clipboard_reorder` 改 created_at → EVT_CHANGED → refresh → queue 重算成新顺序
  （又跳一次）。两次跳变合成"闪一下"。
- 修复：松手时**保持视觉顺序**，先 `reorderQueueEntry(id, overId).then(() => refresh())`
  等后端重排完成、列表刷新（此时 queue 顺序已等于视觉顺序），再清 visualOrder/dragState，
  顺序无跳变即无闪烁。后端 clipboard_reorder 排序逻辑与前端 applyVisualOrder 一致，
  保证了"新队列顺序 == 视觉顺序"。
- 纯前端改动（ClipboardPanel.tsx finishDrag），npm run build 通过。

## VS Code 打开实际启动 Qoder（probe_vscode 顺序修复）
- 现象：右键「用编辑器打开 → VS Code」实际打开的是 Qoder CN。
- 根因：`probe_vscode` 探测顺序是 configured → **PATH code 命令** → 标准安装路径。用户机器上
  `D:\QoderCN\bin\code.cmd` 在 PATH 里排在 `D:\Microsoft VS Code\bin\code.cmd` 前面（where code
  第一行是 Qoder），于是 code 命令被误判为 VS Code；真 VS Code 装在 `D:\Microsoft VS Code`
  （盘根），但探测在第 2 步就返回了 Qoder，没走到盘根扫描。
- 修复：探测顺序改为 configured → **标准安装 + 盘根/scoop**（真 VS Code Code.exe）→ PATH code
  （兜底，排除路径含 qoder/windsurf/cursor 的抢占项）→ 受限全盘扫描。
- 教训：PATH 中的 `code` 命令可能被 VS Code 系 IDE（Qoder/Windsurf/Cursor）抢占注册；
  探测编辑器优先走安装路径而非 PATH 命令。

### 划词翻译（translate.rs 新模块 + translate-popup 窗口 + TranslationPage 设置页）
- 触发：全局快捷键（默认 Ctrl+Alt+T，走 global_shortcut 插件非 Win 组合）→
  `trigger_selection_translate`：保存剪贴板 → keyhook::send_ctrl_c 模拟复制选中文本 →
  延时 180ms 读剪贴板 → 恢复原剪贴板（SUPPRESS_WATCH 防污染历史）→ 调翻译 API → 弹窗。
- API：有道智云（sha256 签名 v3）/ 百度开放平台（md5 签名）；from=auto 自动检测源语言；
  目标语言通用代码 zh/en/ja/ko/fr/de/ru/es，按 provider 映射（有道 ja/ko/fr/es ↔ 百度 jp/kor/fra/spa）。
- 弹窗：TranslatePopup 挂载拉 translate_last_result + 监听 translate://result 事件；
  复制译文走 clipboard_copy_text 不污染历史；失焦/Esc 关闭；定位鼠标附近。
- 新依赖：reqwest(rustls-tls) + sha2 + md-5 + hex。
- 设置：TranslationPage（provider 切换、key/secret/appid、目标语言、测试翻译）；
  ShortcutPage 加 translation 行；tauri.conf.json 加 translate-popup 窗口（420x260）。
- 注意 async 闭包需 'static：AppHandle 先 clone 再 move；primary_monitor 返回 Result<Option<Monitor>>。

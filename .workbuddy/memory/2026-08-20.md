- 修复 `src/modules/toolbar/Toolbar.tsx`（纯前端，Rust toolbar_geometry 物理像素坐标经核查无误）：

  2. 移除 byHover 自动再收起，再收起统一交给 mouseleave + 轮询兜底（消除秒收/消失）。
  3. 启动兜底：窗口完全在显示器外时夹回屏内。

- 经验：dock 类 auto-hide 的恢复触发半径(EDGE_REVEAL)必须小于窗口尺寸(win_w)，否则「离开窗口」(>win_w 距边)与「靠近弹出」(≤阈值距边)冲突会抖动；本例 win_w≥38 > 70? 实际 1 工具时 38<70 仍安全（离开需 >38，阈值 70 仅扩大"贴边常驻"区，无抖动）。

## 贴边收起「整条飞出屏幕 / 靠近不弹出」——高分屏缩放坐标单位错位（Req G，待 commit）
- 症状（主人 8/19 反馈）：一启动靠边收起，工具栏直接收没了（没有露出 4px 边框），
  且鼠标靠近屏幕边缘也不弹出。强调「昨天在另一台电脑正常」→ 不是分辨率问题，是 DPI 缩放。
- 根因：toolbar_geometry（Rust）返回的 cursor/win/monitor 坐标**全是物理像素**；
  而 animateWindowTo() 与启动兜底 setPosition 用的是 LogicalPosition —— Tauri 会把
  LogicalPosition 再乘一次 scale factor。100% 缩放时物理==逻辑不出错（所以另一台电脑正常）；
  125%/150% 缩放下被二次放大，工具栏被推到屏幕外数千像素（整条消失、无细边），
  expandFromEdge 的目标坐标也错乱 → 靠近边缘永远触发不了弹出。
- 修复 `src/modules/toolbar/Toolbar.tsx`（纯前端）：
  1. import 改 `{ LogicalSize, PhysicalPosition }`（剔除不再需要的 LogicalPosition）。
  2. animateWindowTo 内 `setPosition(new LogicalPosition(x,y))` → `PhysicalPosition(x,y)`。
  3. 启动兜底（窗口完全在屏外夹回）`setPosition(new LogicalPosition(...))` → `PhysicalPosition(...)`。
  4. probe() 的 inside/cursorNearEdge/detectEdge 全程用 toolbar_geometry 物理像素，单位一致，无需改。
- 验证：npx tsc --noEmit 通过（noUnusedLocals 开启，导入已清理）；cargo check 命中缓存通过。
- 经验：Tauri 里 outer_position()/outer_size()/cursor_position()/toolbar_geometry 返回的
  **物理像素**，凡是把它们再喂给 setPosition/setSize 时，必须用 PhysicalPosition/PhysicalSize，
  绝不能用 LogicalPosition（除非你明确先除以 scale factor）。高分屏 double-scaling 在低缩放比
  下完全隐形，是最隐蔽的一类 bug。

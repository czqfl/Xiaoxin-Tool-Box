## 文件夹面板终端选择 + 剪贴板图片保真（commit 29f4ed4）

### 1. 文件夹面板可选择终端
- 后端 `folder.rs` 新增命令 `folder_open_in_terminal_with(path, shell)`，shell 取 `wt` | `cmd` | `powershell`；
  原 `folder_open_in_terminal` 保留，改为默认 wt 回退 cmd。
- Windows 下统一用 `CREATE_NEW_CONSOLE`(0x10) 新开独立控制台，避免继承宿主无窗口环境。
- PowerShell 路径用单引号包裹并将 `'` 翻倍转义；cmd 用 `cd /d "path"`（引号转义为 `""`）。
- 前端：右键菜单「在终端中打开」改为 hover 子菜单（ContextMenu 支持 `children`），
  子菜单样式加在 `src/styles/panel.css`（.context-submenu）。

### 2. 剪贴板图片变糊根因与修复
- 根因：`save_thumbnail` 把所有图片压成 200px 缩略图保存，写回剪贴板也读这张图 → 粘贴分辨率丢失。
- 修复：`ClipEntry` 新增 `image_thumb_path`；图片保存原图 `{id}.png`（完整分辨率）+ 缩略图 `{id}.thumb.png`（200px）；
  `clipboard_image_data` 预览优先返回缩略图（旧记录无缩略图回退原图）；
  `write_entry_to_clipboard` 改读原图 → 粘贴保持原分辨率；删除时同时清理两个文件。
- 旧历史记录（image_path 指向旧缩略图）无法恢复原图，属预期限制。

### 约定
- 图片字段语义：`image_path`=主图（原图），`image_thumb_path`=预览缩略图，勿再混用。

## Snipaste 图片进不了剪贴板历史（commit 后补）

### 根因（两点叠加）
1. **arboard 只读 CF_DIB**：arboard 在 Windows 的 `get_image()` 只读 CF_DIB 位图；
   Snipaste 复制图片主要写入 EMF/PNG 格式，DIB 缺失/解析失败时图片被静默丢弃（`if let Ok` 吞错）。
2. **优先级**：原 `read_clipboard` 是「文件 > 图片 > 文本」，若复制内容附带文件列表(CF_HDROP)，
   图片会被误判为文件复制。

### 修复
- `read_clipboard` 优先级改为「图片 > 文件 > 文本」。
- Windows 新增 `read_png_from_clipboard()`：`OpenClipboard` + `EnumClipboardFormats` 枚举，
  匹配名为 "PNG" 的自定义格式，`GetClipboardData` + `GlobalLock/GlobalSize` 读字节，
  用 `image::load_from_memory` 解码为 RGBA 兜底。兼容 Snipaste 和 Win10/11 系统截图。
- Cargo.toml windows features 增加 `Win32_System_DataExchange`、`Win32_System_Memory`。
- **windows 0.61 API 坑**：`GetClipboardData` 返回 `Result<HANDLE>`、`GlobalLock` 返回裸指针、
  `GlobalSize` 返回 `usize`、`GlobalUnlock` 收 `HGLOBAL` 返回 `Result<()>`；HANDLE→HGLOBAL 需 `HGLOBAL(h.0)` 手动包装。

## 打包版全面故障修复（主人 4 点反馈：localhost 拒绝连接 / 托盘无退出 / Esc 贴图卡 / 马赛克失效）

### 1. 核心根因：运行时窗口生产环境误用 devUrl（所有打包故障的源头）
- **现象**：`npm run pack` 后右上角透明窗 + 截图全屏遮罩都显示 "localhost 拒绝连接 ERR_CONNECTION_REFUSED" 且关不掉；`npm run tauri dev` 一切正常。
- **根因**：tauri.conf.json 的 `devUrl: http://localhost:1422` 在打包后**依然存在**（配置文件不会改）。`panel.rs` / `tray.rs` / `screenshot.rs` / `pin.rs` 共 **5 处**运行时建窗逻辑只判断 `app.config().build.dev_url.is_some()` 就用 `WebviewUrl::External(localhost)` —— dev 有 vite server 所以正常，打包后所有运行时创建的窗口（截图遮罩、贴图、重建的面板/设置窗）全去连 localhost → 错误页 + 疯狂重连（CPU 空转 = "很卡"）。
- **修复**：`lib.rs` 新增 `frontend_url(app)` 辅助函数 —— **仅 `tauri::is_dev()` 时用 devUrl，生产一律 `WebviewUrl::App("index.html")`**（打包资源经 Tauri 资产协议加载）。替换全部 5 处调用点 + 清理残留 `WebviewUrl` 导入。
- **可复用经验**：Tauri 里判断"是否 dev"必须用 `tauri::is_dev()`（编译期 dev cfg），**绝不能**只看 `dev_url.is_some()` —— 这是打包后 webview 加载失败的经典坑。

### 2. 托盘右键"看不到退出按钮"
- 代码本身有"退出"项（`MenuItem::with_id(app, "quit", "退出", ...)` → `hard_exit()` TerminateProcess 跳过第三方 DLL 卸载竞态）。
- 加固：菜单加 `PredefinedMenuItem::separator` 分隔线，把「面板开关 | 打开设置/退出」分成两组，退出项更醒目；同时替换动态 `&dyn IsMenuItem` 引用链为显式 push（规避 muda 动态引用模式的潜在渲染问题）。
- 注：无法复现，若重打包后仍看不到需用户截图确认是否旧实例（单实例保护下旧托盘图标残留）。

### 3. Esc 退出贴图卡/不生效
- **打包版根因**：贴图窗加载失败（见 #1）→ 前端 PinWindow.tsx 的 Esc handler 根本没跑；错误页重连导致"很卡"。
- **加固**：keyhook 新增 `Action::HidePinOnEsc`（仿 `CloseTranslate` 先例，不吞键）→ `pin::hide_visible_pin(app)`：
  - 前台是本应用**非贴图**窗口（设置/面板/工具栏）→ 不代劳（Esc 归它们收起自身）；
  - 前台是贴图窗 → 隐藏它（前端未就绪时兜底，就绪时与 webview 自身处理幂等）；
  - 前台是其它应用 → 隐藏最近一张可见贴图（Snipaste 行为）。
- 现在 Esc 无论焦点在哪都可靠退出贴图。

## 剪贴板条目类型标识（主人新需求）
- **需求**：剪贴板条目加类型标识，一眼区分 图片/普通文本/富文本/链接/文件。
- **Rust 端**（clipboard.rs）：`EntryKind` 新增 `RichText`/`Link` 变体（serde → "richtext"/"link"），复制时 `build_entry` 自动分类：
  - `classify_text_kind`：链接（http(s):// / ftp:// / www. / magnet:? 开头）优先级最高（浏览器复制链接常同时带 CF_HTML，URL 语义优先）；否则查富文本；再退普通文本。
  - `clipboard_has_rich_html`（Windows）：枚举剪贴板 "HTML Format" 格式（仿 read_png_from_clipboard 的 Win32 模式），`html_has_formatting` 检查 body 是否含 b/i/u/font/span/color 等格式化标签——纯文本的 HTML 包装不算富文本，避免误判。
  - 写回剪贴板 / 编辑校验：RichText/Link 按文本处理；`clipboard_update_text` 编辑后按新内容重判链接。
- **前端**：`EntryKind` 类型扩展；`ClipboardItem` meta 行新增 `.clip-type` 徽标（图片=青 / 富文本=品牌蓝 / 链接=绿 / 文件=琥珀 / 文本=中性灰，克制用色）；新增 `IconLink`/`IconRichText` 图标；拖拽幽灵图标同步；richtext/link 可编辑。
- 注意：本机工作区常有主人（或其它 AI 工具）未提交的 pin/screenshot 模块改动，与我的改动不重叠时**只暂存自己改的文件**，不连带提交他人 WIP。

## 图片被识别成文件的排查与修复
- **主人疑问**："为什么图片也会被识别成文件"。
- **排查**：配置文件 watch_images/watch_files 均 true；项目 data 历史无 files 条目；安装版 APPDATA 历史 12 条 files 全部来自 explorer（log/zip/html/exe 等真实文件复制），image 7 条全是 snipaste。→ 图片位图复制（Snipaste）正常；问题只发生在**按文件方式复制图片**（资源管理器 Ctrl+C 图片文件、微信等暴露文件路径），剪贴板只有 CF_HDROP 无位图，走到 Files 分支。
- **关键 API 事实**：arboard 3.6.1 `Set::image()` 会先 `empty()` 清空剪贴板再写 PNG+CF_DIBV5——位图与文件列表**不可共存**，粘贴只能按来源二选一。
- **修复**（clipboard.rs）：`build_entry` Files 分支——单个文件且扩展名图片（png/jpg/jpeg/gif/bmp/webp/tif/tiff/ico/avif）且可解码 → `image_file_entry` 生成 Image 类型条目（保存原图+缩略图，显示图片徽标与缩略图），files 保留原路径；`write_entry_to_clipboard` Image 分支优先写回文件列表（资源管理器粘贴=文件）。多文件/非图片/解码失败退回 Files，零回归。
